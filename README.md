
# Unigen

> **用自然语言编写“工作指南”的自指 Agent 系统：一个文件定义一个 Agent，指南即流程代码，LLM 与工具即运行库。运行期可读写自身、生成和调度子 Agent，并可用 Lean / Prolog 等外部验证器校验。也可以当作普通 Agent 使用；早期版本未做执行效率优化。**

Unigen 的核心是支持自指的 Agent。它不发明一门新语言，而是把自然语言直接当作编写 Agent 流程的语言；现阶段这种“程序”的载体是工作指南，系统先服务于 Agent 的编写、修改与调度。一个文件定义一个 Agent：头部配置声明可用工具、Skill、子 Agent、环境与模型依赖，正文写明目标、步骤、分支、交接与校验。多 Agent 协作、动态子 Agent 和验证器校验，都建立在这一自指结构之上。

与常见的对话式 Agent 不同，Unigen 的任务步骤、分支条件、子 Agent 交接与结果校验写在可见的工作指南中；Agent 在运行期可以把自身的工作指南、配置，以及向它开放的工具和子 Agent 资源作为操作对象。

---

## 设计思路

把 Agent 看作一台计算机：传统软件用代码调用函数库；在 Unigen 中，**工作指南就是程序**，LLM 与环境工具是它调用的运行库。围绕“自指 Agent”，Unigen 有三项设计。

### 1. 一个文件定义一个 Agent：工作指南即程序

每个 Agent 对应一份工作指南，由两部分组成：

- **头部配置（Front-matter）**：声明该 Agent 可用的工具、Skill、子 Agent、环境要求与模型依赖。日常使用在图形界面勾选和配置，无需手写 YAML。
- **指南正文（Markdown）**：用自然语言写明任务目标、操作步骤、条件分支、交接顺序与校验方式。

指南的写法随模型能力调整：模型推理能力强时，正文写目标与约束即可；模型能力较弱时，把步骤拆到判断条件和工具调用，同样可以跑通流程。一个文件对应一个 Agent，也使 Agent 可以被独立生成、修改、调度，并在需要时并行编排。

### 2. 自指与自扩展：Agent 在运行期操作自身

自指是 Unigen 的核心。工作指南本身是文件，工具配置也可作为操作对象向 Agent 开放。Unigen 支持工作指南的自指调用：

- 在指南中引用自身，在运行过程中读取或修改指南内容。
- 根据任务需求动态生成新的工作指南，并启动子 Agent 执行。
- 接入外部训练与加载工具后，对模型进行微调并重新挂载。
- 在指南正文中编排多个 Agent 的分工、并行协作、交接顺序与退回条件。

因此，多 Agent 协作不是外挂的流程编排，而是自指结构的延伸：一个文件定义一个 Agent，Agent 可以生成、修改和调度其他 Agent。跨步骤共享数据时使用存储。Unigen 既可用于处理具体业务，也可用于构建、修改和调度其他 Agent（原理详见 [Wiki](../../wiki)）。

### 3. 验证器：给自指闭环加可信校验

Agent 能修改自身，修改结果就需要校验。Unigen 把生成与校验分离：LLM 负责生成方案与执行内容，确定性外部验证器负责核对输出。

- 数学与形式化验证可接入 **Lean** 等证明助手。
- 逻辑规则与约束推理可接入 **SWI-Prolog**（如 s(CASP)、CHR）等符号引擎。

验证器依据规则核对模型输出；逻辑类验证器可生成**论证树（Justification Tree）**，标明每条结论依赖的前提与规则。通过校验后输出最终结果；未通过则返回报错信息，由模型按约束修正或重算。这为 Agent 的自指修改提供了可校验闭环；完整的高可信自改进仍依赖符号验证系统推进，细节与配置见 [Wiki](../../wiki)。

> 以上能力可独立使用。**Unigen 也可以当作普通 Agent 来用**：不启用自指、自扩展和外部验证器时，它就是常规 Agent，通过调整指南详细程度适配不同能力的模型。

## 工作指南与多 Agent 协作示例

单个任务不需要拆成多个 Agent；当任务需要分阶段接力或分工时，可在同一份指南中完成编排。以下示例包含四个阶段，`---` 之间为图形界面生成的头部配置，下方为指南正文：

```markdown
---
name: ecom-visual
description: 电商视觉内容生产协调者。调度定位、风格、分镜、交付四个子 Agent，按阶段接力产出成品。
tools:
  - { type: agent, path: ./steps/briefing-and-positioning.md }
  - { type: agent, path: ./steps/style-direction.md }
  - { type: agent, path: ./steps/shot-design.md }
  - { type: agent, path: ./steps/delivery.md }
---

你是电商视觉设计调度官。客户给的设计资料，要经过四道工序变成可交付的成品。每道工序由专门的子 Agent 执行，上一步的产出就是下一步的输入。

**阶段 A · 定位**：调用 briefing-and-positioning，从原始资料提炼核心卖点、slogan、目标市场。
**阶段 B · 风格**：调用 style-direction，基于阶段 A 的产出归纳目标人群风格与情绪价值，给出唯一的视觉风格令牌。
**阶段 C · 分镜**：调用 shot-design，把风格令牌落成完整的出图规格 `render_spec`。
**阶段 D · 交付**：调用 delivery，消费 `render_spec`，核对全局约束，输出成品。任一约束不满足，退回对应阶段重做。
```

- `type: agent` 指向各个子指南文件；头部配置还支持工具、Skill、环境与模型等声明。
- 阶段 A→B→C→D 的顺序、输入输出传递和退回规则直接写在文本中。某一步结果不符合要求时，定位对应段落修改描述即可。
- 需要并行分工时，同样在指南正文中写明分工、汇总与退回条件；跨步骤共享数据使用存储。

## 与常见方案的区别

| 维度 | 代码框架（如 LangChain / LlamaIndex） | 常见提示词与工作流工具（如 Copilot Studio / Coze） | Unigen |
| --- | --- | --- | --- |
| **核心抽象** | 代码中的链、工具与状态 | 提示词与可视化节点 | 可自指的工作指南：一个文件定义一个 Agent |
| **编写方式** | Python 代码 | 提示词与节点连线 | 界面配置 + 自然语言正文 |
| **协作与交接** | 写在代码逻辑与状态机中 | 依赖路由模型或手工变量传参 | 直接写在指南正文中，支持自修改与动态子 Agent |
| **模型能力依赖** | 随代码控制度变化 | 依赖路由精度与单节点理解能力 | 可调整指南步骤粒度适配弱模型 |
| **结果校验** | 需自行编写断言或校验逻辑 | 依赖模型自检或节点规则 | 支持接入 Lean / Prolog 等外部验证器 |

## 快速开始

从 [Release](../../releases) 下载对应版本，或从源码启动：

```bash
git clone https://github.com/masol/unigen
cd unigen
npm i && npm run start
```

启动后只需三步：**新建项目 → 运行 → 调整工作指南**。

界面以图形化方式配置工具、编排子 Agent 和编辑指南正文，不要求手写 Markdown 或 YAML；如需直接编辑底层文件，源码目录下对应文件同样开放。

## 适用范围

| 适合 | 不适合 |
| --- | --- |
| 有固定步骤、可写成 SOP 的重复流程（如日报整理、客服分流、素材加工） | 每次都需要临场发挥、无法归纳步骤的任务 |
| 会写业务规则但不写代码的运营、客服、内容与分析人员 | 要求纯软件确定性逻辑、不需要 LLM 参与的计算场景 |
| 需要构建多 Agent 协作、Agent 生成 Agent 或接入形式化校验的开发者 | 只需单轮对话问答的场景 |

**关于弱模型适配**：模型推不出来的步骤，可以在指南中拆细规则与词汇；需要严格结论时，可接入外部验证器约束输出。但如果模型无法完成最基本的指代消解，则需更换更高能力的模型。

## 质量检验标准

Unigen 的检验标准不是只能跑通演示流程，而是：**能否用自然语言工作指南写出类似 Hermes 这样的专用 Agent 的能力（先忽略执行效率）**。如果写不出来，那就是 Unigen 的失败。原因很直接：自然语言既然被当作编写 Agent 流程的语言，就必须能表达专用 Agent 所需的角色约束、步骤、工具调用、分支、状态与校验；否则“指南即程序”不成立。

需要说明：当前是早期版本，未经执行效率优化；本项检验先看能力表达与流程正确性，不看吞吐、延迟和成本。

## 常见问题

**需要会写代码或 YAML 吗？**  
不需要。常用配置和指南编写均在图形界面完成，底层文本文件对需要直接修改的开发者开放。

**工作指南和系统提示词有什么区别？**  
系统提示词定义角色和可用工具；工作指南在此基础上写明执行步骤、判断条件、子 Agent 交接顺序以及校验方式，是一份可执行的工作流程，也是 Agent 自指的载体。

**只能用来做多 Agent 吗？**  
不是。**Unigen 可以当作普通 Agent 来用**；多 Agent 协作、自指和外部验证器都是可选能力。

**Agent 执行出错怎么办？**  
查看执行日志定位出错步骤，在界面中修改对应段落的描述或补充约束条件；接入了外部验证器时，可根据验证器返回的错误或论证树调整规则。如果模型无法理解基础指令，再考虑更换模型。

**支持哪些模型？**  
支持主流云端模型（如 OpenAI、Claude）及本地部署模型。可根据模型能力调整指南的详细程度。
