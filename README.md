# Unigen

**一个可以用“工作指南”调整的 Agent。写清楚你的工作方式，它照做。**

Unigen 首先是一个 Agent（支持多 Agent 协作、MCP、Skill、私有知识库）。和其他 Agent 不同的是：**它的行为不是黑盒，也不只能靠改代码来调整**。你用自然语言写一份工作指南，在图形界面里勾工具、拖子 Agent，Unigen 把它编译成一个能按你方式干活的 Agent 系统。

普通人不写一行代码，也能把 AI 真正用起来。

---

## 它解决什么问题

大多数人和 AI 之间隔着一道缝：AI 很聪明，但它**不懂你的业务具体怎么干**。

你用聊天框交代一遍，它做完了，下次还得重新交代。想把它固化下来，面前通常只有两条路，都不顺手：

**写代码（LangChain / LlamaIndex）** 。要会 Python，精力耗在胶水代码、调度和工程细节上，离业务越来越远。

**用意图生成工具（Copilot Studio / Coze 一类）** 。它们能生成可复用的执行单元——Copilot Studio 的 Skill、Coze 的 Skill——把一段流程封装起来。问题不在“能不能封装”，在于**封装之后，单元之间怎么协同**。Copilot Studio 靠生成式编排器按需加载 Skill 并路由，但路由精度随可选动作数量增加而下降，多级 Agent 链式调用也有明确限制；Coze 的 Skill 通常是独立的 LLM 调用，上下文不会自动延续，需要你在工作流里手工变量传递，而“创作意图”“选题方向”这类软信息在多次传递中会被稀释。结果是：**单个 Skill 能跑，多个 Skill 接力时过程不可控、软信息流失、协同沉淀不下来**。

**Unigen 是第三条路。** 你不写代码，也不只描述目标——你写**一份贯穿始终的过程**：第一步做什么，第二步做什么，什么条件调用哪个工具，什么情况交给哪个子 Agent，什么条件转人工。这份指南同时覆盖**单个节点内部的过程控制**和**节点之间的协同编排**。Unigen 把它连同工具、子 Agent、存储配置，编译成一个完整的 Agent 系统。

> 一句话：别人给你可复用的 Skill，Unigen 给你一份可编辑的**协同说明书**——Skill 能干什么，和 Skill 与 Skill 之间怎么接力，在同一个地方写清楚。

## “工作指南”到底是什么

如果你用过 Agent，可以把工作指南理解为：**系统提示词 + 工具编排 + 分步骤的过程指令**。

但比“写系统提示词”多走了一步。系统提示词告诉 Agent“你是谁、你能用什么工具”；工作指南还要告诉它**“这件工作在你这儿，具体该怎么一步步做，做完一步之后下一步交给谁”**。

一个 Agent = **front-matter（能用什么）+ 指南正文（怎么用、怎么协同）** ：

- **front-matter** 配置结构：挂哪些 MCP / Skill / 子 Agent。这部分在图形界面里勾选和拖拽完成，不需要手写 YAML。
- **指南正文** 就是工作指南本身：用自然语言写清楚步骤、条件、约束、交接关系。像给新员工写 SOP，也像用自然语言写程序——只是执行者从编译器换成了 LLM。

指南写粗还是写细，由你按模型能力定：模型强的地方一句带过，模型没把握的地方把节点切细、约束写死。同一套底座，靠这一份指南适配从前沿大模型到本地小模型。

## 多 Agent 怎么接力

单 Skill 能做到的事，不必用 Unigen。下面这个例子是它理想的场景——四道工序、四个子 Agent，协同关系全部写在同一份指南里。`---` 之间是 front-matter，由 GUI 生成；下面是指南正文。

```markdown
---
name: ecom-visual
description: 电商视觉内容生产协调者。调度定位、风格、分镜、交付四个子 Agent，按阶段接力产出成品。
tools:
  - { type: agent, path: ./steps/briefing-and-positioning.md }
  - { type: agent, path: ./steps/style-direction.md }
  - { type: agent, path: ./steps/shot-design.md }
  - { type: agent, path: ./steps/delivery.md }
---

你是电商视觉设计调度官。客户给的设计资料，要经过四道工序变成可交付的成品。每道工序由专门的子 Agent 执行，上一步的产出就是下一步的输入。

**阶段 A · 定位**：调用 briefing-and-positioning，从原始资料提炼核心卖点、slogan、目标市场。
**阶段 B · 风格**：调用 style-direction，基于阶段 A 的产出归纳目标人群风格与情绪价值，给出唯一的视觉风格令牌。
**阶段 C · 分镜**：调用 shot-design，把风格令牌落成完整的出图规格 `render_spec`。
**阶段 D · 交付**：调用 delivery，消费 `render_spec`，核对全局约束，输出成品。任一约束不满足，退回对应阶段重做。
```

`type: agent` 的每一项指向一份子指南文件，正文里的阶段 A→B→C→D 就是它们的接力顺序。关键区别在于：**交接关系写在指南正文里，是显式的、可读的**——不是交给编排器去猜，也不是靠变量逐层搬运(Unigen也支持，不过大多数情况用不上)。上游的输出就是下游的输入，像函数调用一样传递。哪一步出了问题，改哪一段文字即可。

## 快速开始

从 [Release](../../releases) 下载对应版本，或从源码运行：

```bash
git clone https://github.com/masol/unigen
cd unigen
npm i && npm run start
```

打开后三步：**新建项目 → 运行 → 有问题改指南**。

界面是图形化的：配置工具、编排子 Agent、富文本写指南正文，全程不碰 Markdown、YAML、front-matter 语法。对想直接编辑底层文件的高级用户，那份文件也开放，但不是必须。

## 适合谁，不适合谁

| 适合 | 不适合 |
|---|---|
| 想把一段**固定流程**交给 AI 持续执行的人——日报、客服分流、素材整理、固定分析步骤 | 每次都需要**全新创造性思考**、没有固定过程可固化的任务 |
| 会写业务 SOP、但不写代码的运营 / 客服 / 内容 / 分析人员 | 需要**完全确定性**的传统软件逻辑，而非 LLM 推理驱动的流程(未来特性) |
| 想快速搭多 Agent 系统、不想陷进胶水代码的开发者 | 只需要单轮问答、不涉及多步协同的极简场景（网页版有免费额度，但API没有） |

**模型弱也能跑。** 这是设计选择，不是事后补丁。模型推理不到的地方，你在指南里替它写明白；词汇对齐它见过的世界，步骤切到它能照做。强模型写粗，弱模型写细，旋钮在你手里。但如果模型弱到连基本指代消解都不过关，任何指南都无力——这不是粒度问题，是模型能力下限问题。

## 常见问题

**要会写代码或 YAML 吗？**
不需要。图形界面覆盖常用配置。底层文件对高级用户开放，但普通用户全程在界面里完成。

**工作指南和系统提示词到底差在哪？**
系统提示词告诉 Agent“你是谁、有什么工具”；工作指南在此基础上把**过程**写进去——先做什么、再做什么、什么条件走哪条路、做完交给谁。写系统提示词是在描述一个角色，写工作指南是在定义一套**可执行、可交接的工作流程**。

**和 Copilot Studio / Coze 到底什么区别？**
它们也支持多 Agent 和可复用单元，这一点需要承认。区别在于**协同的控制方式**：Copilot Studio 靠生成式编排器决定每个 turn 由哪个工具、知识源或连接 Agent 处理，控制感取决于 Instructions 和 Descriptions 的质量以及编排器的路由精度；Coze 的 Skill 独立调用，跨 Skill 的上下文需要显式传递。Unigen 让你把**协同本身**写进同一份工作指南——谁在什么条件下接手、交接什么、退回哪一步——而不是把协同交给隐式路由或手工搬运。这不是“有或没有多 Agent”的差别，是“协同过程是否可读、可编辑、可沉淀”的差别。

**和 LangChain 什么关系？**
LangChain 用 Python 编排 Agent，Unigen 用自然语言工作指南 + 图形界面编排 Agent。能力有重叠，面向的人不同：前者给开发者，后者给想把业务交给 AI 的普通人。

**Agent 执行错了怎么办？**
看执行日志，定位到哪一步，在图形界面里改那一步的描述。指南就是控制面。但前提是：错误出在**过程描述**上，而不是模型根本“听不懂”你用的词。如果是后者，先换措辞或换模型，再改指南。

**支持哪些模型？**
主流 LLM 均可（OpenAI / Claude / 本地模型）。按模型能力调整指南粒度即可。

## 能力底座

| | 说明 |
|---|---|
| **兼容 MCP 与 Skill** | 已有 MCP Server、Skill 直接接入，零改造。front-matter 里用 `type` 区分工具来源。 |
| **多 Agent 协作** | 调度官按阶段调用子 Agent，交接关系写在指南正文里；需要跨步骤共享上下文时用存储。 |
| **私有知识库** | 每个 Agent 可挂载私有数据，执行前检索相关上下文，用约束收敛决策。 |
| **多种存储通信** | KV、向量、模板变量，供多 Agent 读写协作。 |
